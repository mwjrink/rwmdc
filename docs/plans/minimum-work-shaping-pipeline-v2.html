Fewer passes. Explicit ownership. Ordered shaping.

Brief, including the follow-up

Plan the proposed five-step shaping pipeline and correct the three selection defects. Eliminate translation into and out of the newer glyph representations, rather than merely making those translations cheaper. Decide whether to start a new shaper or replace the execution core inside the existing owned KB implementation.

Replace KB's execution core, not its accumulated shaping knowledge. One canonical glyph representation runs from initialization through normalization, GSUB, GPOS and output. Scratch uses that same representation. Remove full-stream format bridges instead of optimizing around them.

Scope: the owned KB shaper, its existing high-level run preparation, and benchmark adapters. No editor integration, new thread pool, Unicode-version upgrade, or replacement of the approved fixed-depth candidate matcher. Existing approved plans remain unchanged.

Decision

A clean execution core inside the existing shaper

Reuse the expensive knowledge

Keep font parsing, selected cmap semantics, pinned Unicode data, script preparation algorithms, feature selection, compiled rule programs and the approved fixed-depth matcher. Preserve native substitution and positioning semantics, including their difficult edge cases.

Port their buffer access and mutation code where needed. Reusing an algorithm does not mean keeping its old storage adapter.

Replace the execution plumbing

Remove the canonical glyph → hot-row → pending-span → emitted-row → canonical glyph round trip. Rewrite affected matchers and actions to consume the same live indexed glyph storage directly.

Keep immutable font lookup data in its specialized formats. Font tables and glyph buffers have different jobs; “one glyph representation” does not mean flattening every table into one structure.

Concrete first representation: retain the existing indexed kbts_glyph array as canonical and use the same record type in any spare output buffer. This keeps normalizers, native actions, GPOS and public output on a common representation without inventing another compact intermediate. Optimize record layout only as a separate end-to-end change, never by adding a mirror.

Migration rule: bring over coherent execution paths, not adapters. Compiled and native lookups may be migrated incrementally because both consume the same canonical buffer. No shipped path translates into an old engine and back. Preserve old behavior in standalone control executables, not as a second production runtime.

Translation budget: zero full-stream glyph-format conversions between normalization, GSUB and GPOS. UTF-8 decoding and initial glyph mapping are real semantic transformations; same-format emission for length changes and one explicitly requested output packing pass are not forbidden. Small read-only matching windows and indexes remain legitimate derived data, but must be counted and justified.

01

The proposed data flow

Remove the current layering cost

Full glyph records → gathered hot rows → stage/position bitmaps → initialized spans → pending rows → emitted rows → cold-record synchronization.

Delete this full-stream round trip. Merely skipping it on unchanged stages is not the final architecture.

Target ownership

Prepared input is read-only. Run spans are views. Initialization, normalization, compiled/native GSUB, GPOS and output share the same canonical glyph record type.

Derived matching windows are temporary read-only data. Spare output uses the same type as live input. There is no second mutable full-stream glyph format to synchronize.

Logical stages are not physical copy passes. Font fallback and normalization may consult the same cmap before final glyph initialization; there is no claim that mapping is used only once or only after itemization.

“Two buffers” means two glyph work buffers, not two total allocations. Immutable UTF-8, retained paragraph input/source records, run descriptors, lookup tables, attachment metadata and an optional owned output have their own lifetimes. Do not reuse decoded storage while unprocessed spans still reference it. Report all of this memory.

No hidden bridge: A and B are the same glyph type. A swap changes ownership and count, not representation. GPOS receives the active canonical buffer directly. Final public glyph iteration does not reconstruct full glyph records from a compact internal mirror.

02

Your five steps, made precise

1 · UTF-8 → prepared input, without a redundant source copy

Read the caller's bytes directly. Emit code points and source associations once. For the existing high-level API, reuse its prepared-input records; do not add another UTF-32 mirror. For a presegmented single-font run, decode directly into the glyph initialization path and avoid the intermediate decoded array.

  • ASCII needs no bit assembly: byte value equals scalar value. Reuse the pinned ASCII/Unicode property data already present; derive only properties consumed by the selected path.
  • For non-ASCII, compare the existing scalar decoder with a small byte-class/state LUT implementation. A LUT still needs a code-point accumulator, variable-length output handling and boundary/error checks; it is not a stateless byte substitution.
  • Preserve malformed-input behavior at public input boundaries. Skip validation only when an existing valid-UTF-8 contract actually guarantees the entire supplied slice. SIMD must not overread the tail.
  • Record cheap run summaries while input is already being visited. Do not infer that ASCII allows all font-aware normalization or GSUB/GPOS to be disabled.

Buffer decision: one producer write; no copied UTF-8 input and no mandatory swap.

2 · Prepared input → resolved run spans, without copying payloads

Ordinary Latin letters and Arabic letters belong to separate shaping runs. But raw script changes alone are not safe work boundaries. Use the existing script-extension, combining-sequence, direction and font-resolution machinery before publishing a span.

  • Resolve Common/Inherited characters, punctuation, brackets, marks, joiners and selectors with their context. Do not split a base from a combining mark solely because their Script values differ.
  • Resolve paragraph bidi state before treating directional runs as independently shapeable. Arabic digits can have a different direction from Arabic letters. Paragraph/line visual ordering remains a later layout concern.
  • Use font identity, resolved script, language and direction/level context to choose the run's shaping environment. Language comes from caller metadata, not script detection.
  • Feature ranges stay attached to source positions; do not turn every feature change into a hard shaping boundary that destroys contextual matching. Font/style boundaries can require retained joining context; they are not automatically independent chunks.
  • A work unit declares a write range and the context it may read. If a boundary is not proven safe or its context cannot be supplied, keep the containing shaping unit intact. Do not split long runs just for smaller jobs.

Span contract: stable input [first, end), source association, selected font/configuration, resolved direction context, and boundary/context information. These are input indices, not mutable glyph offsets. Store each run's resulting output range separately because shaping changes glyph counts.

Buffer decision: emit descriptors only. The input array stays put. Execute serially initially; no thread scheduler is required to gain this representation benefit.

3 · Selected cmap → exact, cheap nominal glyph mapping

Minimize lookup cost under a measured memory budget, not bytes at any price. Compile/cache by font face, not by script or language. The existing kbts_CodepointToGlyphId dispatches on cmap format and searches format-4 segments or format-12 groups.

  • First candidate: uint16_t ascii_glyph[128], 256 bytes per font, built from the selected cmap once. A supported ASCII query becomes an indexed load after the range check. Keep glyph 0 for missing mappings.
  • For non-ASCII, compare the existing segment/group representation against a deduplicated paged LUT. Share empty/identical pages and measure directory overhead. A 256-code-point page design with a flat 32-bit directory alone costs 17 KiB; it is not automatically tiny.
  • A full 16-bit Unicode map is 2.125 MiB per font. Do not allocate that by default. Preserve arithmetic ranges where they are cheaper than expansion.
  • Do not collapse distinct glyph IDs into one contextual matching symbol. Matching equivalence does not imply the same glyph outline or metrics.
  • Keep selectors and source associations available. A base-plus-variation-selector mapping is a separate semantic operation, not an ordinary scalar cmap lookup. This optimization preserves existing supported behavior; it does not silently claim new format/variation support.
  • Normalization can decompose, compose or reorder using font coverage. It may need more mapping queries. Reuse the same mapping acceleration there and in fallback checks.

Buffer decision: mapping writes the glyph ID and required metadata during glyph initialization, or updates existing record fields in place. Do not copy an entire record merely to replace its glyph ID. Retain code points until their normalization/context consumers finish.

4 · One canonical buffer through ordered substitutions and positioning

Build the selected lookup schedule once per configuration. Preserve script-specific stages, required/enabled features, reachable contextual child lookups and original lookup/subtable/rule priority.

  • Keep the approved fixed-depth candidate matcher and its all-stage evaluation contract. Adapt its input gather to the canonical glyph array; do not translate the entire run into another glyph format to invoke it.
  • Compiled and native actions read and write the same live glyphs. Use ordinary positions for scans and stable identities only where mutation, attachment or continuation requires them.
  • Remove kbts__gsub_row mirrors, pending-row translations, explicit unchanged-slot spans and cold synchronization paths after their consumers have been ported. Their replacement is direct access, not a renamed converter or a run-sized lazy cache.
  • Compute coarse stage admission directly where possible instead of repeatedly collapsing lookup bits into stage bits. Preserve dynamic feature/flag checks and update derived indexes when changes invalidate them.
  • Same-length substitutions normally update live state in place. Refresh all matching-visible consequences: ID, symbol, class, flags and relevant eligibility. Later lookups must observe earlier writes.
  • A→B emission uses the same canonical record type and requires snapshot-safe reads or explicitly correct sequential forwarding. Otherwise execute the ordered action directly on live storage; there is no call into an old representation.
  • Handle output expansion with checked growth, source/cluster and attachment identity preservation, and commit only after successful emission. Repair position-dependent indexes on actual reindexing.
  • Metrics, native GPOS and attachment/final-position fixups consume the same canonical array. Preserve their algorithms, but change their storage access if necessary to meet this invariant. Do not postpone a GSUB→GPOS format bridge as a “later optimization.”

Buffer decision: no change means no emission; same-length live updates need no swap. A completed out-of-place transform swaps active/spare buffers and counts. Reuse scratch at run scope. Queues are optional accelerators, not a required pipeline stage.

5 · Positioned glyphs → borrowed result or one final packing pass

Step 4 is complete only after metrics, GPOS and attachment/final-position fixups. Then step 5 should normally expose its output, not run shaping again.

  • Keep the existing direct API's glyph IDs, user IDs, positioning values, iteration order and lifetime semantics. Its RTL output convention is left-to-right visual order; do not silently change it to logical order.
  • A caller able to consume current glyph storage receives the existing iterator/view without a mandatory whole-array copy. A caller requiring packed, independently owned records gets one explicit final projection into its destination.
  • The current benchmark already performs this projection to BenchGlyph. Preserve identical consumer work in before/after measurements; do not claim a win by excluding output extraction.
  • Keep source/cluster provenance through contractions, expansions and reordering. The decoder may use byte offsets as user IDs; arbitrary low-level caller-supplied user IDs remain opaque and preserved.
  • After multiple runs, output counts determine output ranges. Do not reuse original code-point span offsets as glyph offsets or concatenate RTL/LTR runs as a replacement for bidi line layout.

Buffer decision: borrowed results expire according to existing storage rules; persistent results require caller ownership or a copy. Final run order/line layout remains outside this shaper refactor.

03

Implementation order and acceptance gates

One coherent, measured change at a time. Translation removal is the first structural milestone, ahead of decoder and cmap tuning. Within that milestone, port producers and consumers together on the shared canonical representation; no intermediate production format adapters. Preserve controls as separate executables and remove rejected experiments rather than accumulating runtime modes.

  1. M0

    Freeze controls and count the work

    Preserve current and pre-span executables plus build flags, inputs, font identities and checksums. Use existing profiling facilities and disposable probes to count copied bytes, full scans, identity resolutions, cmap queries, bitmap clears and rebuilds. Keep these counters out of timing builds.

    bench/shaping.c · bench/shaping_kb.inc · kb_profile.h

    Gate: comparable core and end-to-end measurements; phase boundaries are explicit. Current whole-process PMU counts remain labelled as such. Add scoped counters only if their instrumentation cost is measured.

  2. M1

    Correct script/language selection before optimizing it

    Remove arbitrary first-script fallback; use the applicable script, then DFLT, otherwise no unrelated-script lookup plan. Add Language to the existing font/script configuration-cache key. Include LangSys RequiredFeatureIndex and deduplicate/order its lookups correctly with selected optional features. Preserve reachable contextual children and a script's intentionally absent LangSys.

    kb_text_shape.h: kbts__PlaceShapeConfig · kbts__FindOrCreateShapeConfig · feature enumeration

    Gate: spec-driven fixtures cover a missing Latin/DFLT script, a context reused across languages with different visible substitutions, and a required-only LangSys with an observable substitution. Keep these three regression tests. Ordinary workloads retain output parity; intentional corrections are not hidden by blanket oracle exceptions.

  3. M2

    Replace the translation-based execution core

    Keep the indexed canonical glyph array and port compiled matching, action emission and native-stage dispatch to it directly. Normalization, native actions and GPOS already use canonical storage; make all affected access paths agree without a full-stream hot-row bridge. Use direct positional scans where valid. Spare output uses the same glyph type. Remove row gathering, pending-row reconstruction, explicit unchanged spans and cold synchronization as each complete path is migrated.

    Reuse the existing native substitution and positioning algorithms, adapting state access rather than translating their input. Preserve symbols, classes, flags, source IDs, attachments, continuations, forward/reverse traversal, fixed-arena behavior and failure semantics. Include targeted no-change and mutation-heavy runs; do not change cmap or candidate-evaluation logic at the same time.

    kb_gsub_stream.h/.inc · kb_context_match.inc input gather · kb_execute_op.inc · canonical storage, native GSUB and GPOS access

    Gate: zero full-stream glyph-format conversion bytes between normalization, GSUB and GPOS; all production paths use the canonical type, including uncommon scripts and native fallbacks. Matching-window gathers and actual same-format emissions are measured separately. Complete output equivalence and repeated performance improvement are required. If direct canonical access loses locality, improve access on this representation; do not restore the bridge or declare an ASCII-only cutover finished.

  4. M3

    Make input and run ownership explicit

    Expose resolved run boundaries as index descriptors over existing prepared input, preserving the current resolver rather than replacing Unicode/bidi algorithms. Reuse source metadata and current API conventions. Keep presegmented decode→glyph preparation fused; trial the non-ASCII decoder LUT only against the existing path. Any unsafe boundary discovered by the mixed-script witnesses is corrected locally before spans are declared independent.

    kb_text_shape.h: input preparation · script resolution · kbts_ShapeRun · benchmark input adapter

    Gate: mixed Latin/Arabic with digits and brackets, inherited and script-specific marks, joiners, selectors, supplementary code points, isolates and font boundaries preserve resolved context and source mapping. No added input-payload copy. Tiny runs are measured as well as long runs.

  5. M4

    Accelerate the exact selected cmap

    Implement and measure the 256-byte ASCII map first. Then compare non-ASCII paged/deduplicated mapping against the existing selected format. Retain only the measured winner; reuse the same map for initialization and coverage/normalization queries. Allocate/free it with the existing font lifetime.

    kb_text_shape.h: kbts_CodepointToGlyphId · kbts__InitializeGlyph · font construction/destruction

    Gate: exact glyph IDs for all valid scalars on supported fixture cmaps, including holes, zero mappings, delta/range boundaries and supplementary groups. Isolate pre-existing specification discrepancies instead of silently baking them into the table. Report mapping bytes, setup cost and lookup/end-to-end timing for sparse Latin and dense CJK fonts. Allocation failures preserve the API's error behavior.

  6. M5

    Reduce scheduling work on the canonical core

    With M2's translation-free execution in place, replace lookup-to-stage scatter with stage-level admission where valid, preserving per-anchor dynamic feature and flag checks. Compare direct in-place actions and same-format scratch emission only for proven-safe transform boundaries. Update derived candidate/symbol indexes locally for same-length writes and repair them on real reindexing. Keep the fixed-depth matcher unchanged; grouping lookup metadata still does not imply grouped execution.

    kb_gsub_plan.inc · canonical GSUB execution · candidate and symbol indexes

    Gate: later lookups observe newly created matches, changed glyph classes and filtering metadata. Overlapping writes, expansion/contraction and reverse substitution preserve order and source identity. Shrink→grow reuse exposes no stale candidate bits. No unchanged-stage copy, unconditional flip, representation bridge or newly introduced full-stream mirror.

  7. M6

    Finalize directly and verify the complete pipeline

    Expose the positioned active buffer through the existing API. Keep at most one required consumer packing pass, explicitly timed. Migrate every affected iterator, fixed-memory path, benchmark caller and test; remove obsolete buffers, fields, adapters and experimental alternatives. Update existing documentation with measured results and remove disposable probes after the successful smoke run.

    kbts_ShapeDirect · kbts_ShapeRun · glyph iterator · bench/shaping_kb.inc · existing shaping docs

    Gate: full correctness checks pass and output ownership/order are unchanged. Run one final project validation after the implementation is coherent. The final performance comparison includes both the original current control and the pre-span control, not just the immediately preceding edit.

Timing and memory protocol

  • Alternate old/new executable order, pin the same core, use the same font, features and changing inputs. Start with the established 1,000 iterations × 5 batches and at least three paired repetitions.
  • Report input, shaping core, output and total separately, plus setup, retained bytes, bytes copied and warm allocations.
  • Measure instructions, cycles, branches/misses and L1D events without multiplexing. If counters must be split, run matched event groups.
  • Accept repeatable improvement beyond paired-run variability. Reject reproducible >2% end-to-end regressions on representative workloads; noisy comparisons remain inconclusive, not wins.
  • A pure memory tradeoff that slows execution needs an explicit user decision; it is not accepted as an optimization.

Workload and correctness coverage

  • ASCII code and prose at 64 B, 4 KiB and 64 KiB; Arabic, Thai/Lao, Indic, combining-heavy and dense-CJK input at short and larger sizes.
  • Run existing five-feature-mode and multi-font owned/upstream comparisons; the immutable vendor header is never edited.
  • Use high-level mixed-script/context witnesses in addition to the low-level presegmented benchmark. Existing differential stress does not prove paragraph bidi correctness.
  • Exercise fixed arenas, unaligned storage, growth failure, zero-length input, source IDs and borrowed-output invalidation under ASan/UBSan.
  • Keep permanent tests only for observable uncertain boundaries or discovered bugs. Representation/throughput experiments use disposable probes.
Overall target: recover the pre-span performance loss without losing its later correctness coverage, then demonstrate additional end-to-end savings. Re-measure the preserved pre-span control in the same environment; 368.3 µs is a historical observation, not an absolute pass/fail threshold.

06

Review decisions

Recommended decision

Replace the execution core inside owned KB, rather than creating a second shaper or merely tuning its converters. Require one canonical glyph representation across initialization, normalization, GSUB and GPOS, same-format scratch output, resolved run views and one optional final consumer projection. Translation removal is M2, not deferred until after LUT tuning.

Decision owner: user · approval is for this plan, not a performance claim

No unresolved prerequisite prevents beginning M0–M2. Non-ASCII cmap layout and safe buffer-swap opportunities are settled by the specified experiments. An inability to meet performance or correctness gates is a reported blocker, not permission to leave converters, a script-limited replacement, or a second production engine in place. A compact-layout redesign would require migrating every consumer, not introducing another intermediate representation.
