Fixed-depth candidate LUTs

Review corrections

Keep equal-key candidates consecutively in priority order. Do not use explicit miss/hit links. Pad shorter paths so every candidate evaluates A, B, C, … even after an earlier test fails or the original rule has no more tests.

Corrected recommendation: contiguous priority buckets plus fixed-depth candidate columns. Stage A[c], B[c], C[c], … describe the same candidate. The candidate index itself encodes the next-stage offset, so no child or failure pointer is needed. D is selected only after the complete path matches.

1. Contiguous candidates, not failure links

The initial (program, matching-symbol) lookup returns a half-open candidate range. A bucket [15, 17) means candidates 15 and 16 belong to this key; 17 belongs to the next bucket. Store the range rather than checking the key again at its end.

Each candidate accumulates validity across all stages. Partial matches do not block later candidates. Evaluate candidates without performing actions; select the first full match in priority order, including blockers.

2. Fixed-depth columns make next offsets implicit

// Compact format for the measured bounded calt predicates.
struct Test {
    int8_t  probe_offset;
    uint8_t predicate_id;
};                         // 2 bytes

Test stage[K][candidate_count];
uint16_t outcome_index[candidate_count];

// Candidate c uses stage[0][c], stage[1][c], ... .
// No next pointer: advancing the stage chooses the next table.
valid = 1;
for (k = 0; k < K; ++k) {
    t = stage[k][c];
    symbol = live_symbol_at(anchor, t.probe_offset);
    valid &= (predicate_mask[t.predicate_id] >> symbol) & 1;
}

There is no early exit when valid becomes zero and no early terminal after a short rule. Every candidate runs exactly K tests. In the measured source rules K = 6, probe offsets fit signed 8-bit, and predicate IDs fit unsigned 8-bit. Compute K and field widths after normalization/fusion; these are not universal limits on fonts.

Padding a short rule

Append tests using an ALWAYS_TRUE predicate and a safe probe such as offset zero. For the current 32-symbol alphabet, ALWAYS_TRUE is 0xffffffff. It occupies predicate ID 32, following the 32 real predicates.

The accumulated valid bit preserves any earlier failure. Padding does not convert a failed path into a match.

Inactive SIMD lanes are different

Unused candidate lanes start with valid = 0 and use safe dummy records. Padding inside an active short rule must pass; an inactive lane must never win.

ALWAYS_TRUE padding, no-match outcomes, successful blockers, boundary symbols, and dead glyph slots are separate concepts. SPC remains a real glyph.

3. SIMD across candidates at one anchor

Candidate matching is read-only until the winning rule is selected. Therefore candidates for the same anchor can be evaluated in SIMD lanes without the cross-anchor mutation dependency discussed in the first proposal.

valid = active_candidate_lanes;
for (k = 0; k < K; ++k) {
    tests = load_contiguous(stage[k] + candidate_base);
    symbols = probe_live_symbols(anchor, tests.probe_offsets);
    valid &= test_membership(symbols, tests.predicate_ids);
}

Stage records are contiguous across candidates. Fully duplicated paths avoid next-node gathers and make the candidate loop easier to vectorize. Symbol probes and predicate access can still require shuffles or gathers; padding does not guarantee compiler auto-vectorization. Inspect generated code and use RDTSCP measurements before claiming a speedup.

Only defer the winning action when dependencies permit. Keep resume and dependency metadata hot; the large D payload can be prefetched. Do not match later dependent anchors against state whose preceding actions are still pending.

4. Measured shape and estimated supporting tables

The read-only census found 292 nonempty (lookup, symbol) buckets. Each source rule belongs to exactly one such bucket for this font: there are 802 candidate occurrences, not a class-expansion multiplication. Buckets average 2.75 candidates and the largest contains 9.

5. Construction and flattening

  1. Normalize source rules

    Preserve program/lookup order, full-rule priority, input versus context boundaries, flags, feature guards, ordered actions, and resume semantics. Keep full-width fields in the compiler IR.

  2. Classify and bucket

    Partition glyphs by exact predicate memberships. Group rules by (program, first matching symbol), retaining priority order within each bucket. Duplicate a rule into multiple buckets if its first predicate covers multiple symbols; the measured font happens not to require this.

  3. Build candidate paths

    Each ordered candidate is one complete conjunction of tests leading to an outcome. An intermediate tree/DAG may help construction, but priority is carried by candidate order rather than miss edges.

  4. Fuse only proven rewrites

    Compose local transitions such as the guarded <=> chain only when the resulting compound action preserves all guards, writes, source mapping, and advancement. Keep program ordering for remaining dependencies.

  5. Pad to K

    Choose a common test depth per compiled program or compatible batch. Append ALWAYS_TRUE tests to short candidates. Preserve the outcome separately, so all padding can be identical and does not lose which D record belongs to the candidate.

  6. Flatten by stage

    Assign contiguous candidate IDs by bucket and priority. Write all stage-A records together, then stage B, and so on. The implicit transition is the same candidate ID in the next array. Emit candidate ranges, outcome indices, and hot/cold metadata separately.

  7. Measure before sharing runtime paths

    Shared suffixes would require explicit child indices or another indirection. Since unshared Test records are only two bytes and the measured test matrix is 9.4 KiB, start with duplicated columns. Add runtime DAG sharing only if its saved bytes outweigh the lost contiguous access and added indexing.

6. Evidence and remaining verification

In-memory matching check: the fixed-depth packed representation selected the same first matching rule as unpadded glyph-set predicates in 10,146 deterministic witness/randomized cases. Zero selection mismatches; 420 cases selected successful blockers. Candidate ranges were contiguous.

This checks packing, relative probes, padding, and rule selection for the inspected unfiltered calt predicates. It does not verify a SIMD implementation, action execution, compound fusion, filtered traversal, feature-range handling, complete shaping output, or runtime speed. Those remain acceptance criteria for implementation, not results of this design exercise.
