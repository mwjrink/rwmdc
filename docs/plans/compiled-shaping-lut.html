Brief

“What is the structure we actually need of the LUT” and “How do we construct it?” Keep matching compact, use offsets between stages, keep action payloads separate, preserve priority through duplicated branches, and build an ordered graph before flattening it.

Recommendation: an ordered decision DAG with explicit success and failure edges, flattened into indexed arrays. Keep each lookup’s execution order. Duplicate nodes when their priority continuation differs. Use a two-destination compressed transition row instead of a full glyph-indexed row at every node.

1. Separate matching from action data

A terminal supplies an action ID for a separate payload table D. Large replacement sequences and positioning programs need not occupy L1. The metadata required to decide whether matching can continue must stay hot.

Hot arrays

  • Glyph-to-symbol classifier.
  • Predicate membership masks.
  • Per-program roots and compact nodes.
  • Small outcome descriptors: action ID, resume/dependency plans, and scheduling requirements.

Separate payload table D

  • Replacement glyph sequences and glyph-dependent maps.
  • Ordered nested actions and numeric positioning data.
  • Attachment and source-mapping instructions.
  • Compound actions produced by verified fusion.

No-match, successful blocker, and successful action remain distinct outcomes.

2. Compact transition rows

A test asks whether one logical glyph position belongs to one predicate. Its outgoing transition row has only two different answers: hit or miss. Store those two destinations rather than repeating them across a dense alphabet row.

// Proposed compact unfiltered/bounded-probe backend: 8 bytes.
struct MatchNode {
    int16_t  probe_offset;
    uint16_t predicate_id;
    uint16_t next[2];       // miss continuation, hit continuation
};

// Conceptual traversal. live_symbol_at provides valid logical access.
while (!is_terminal(state)) {
    n = nodes[state];
    s = live_symbol_at(anchor, n.probe_offset);
    hit = (predicate_masks[n.predicate_id] >> s) & 1;
    state = n.next[hit];
}
outcome = terminal_index(state);

This is a uniform kernel with data-selected transitions, not a promise of equal iteration counts. Misses follow compiled failure edges; they do not unwind a runtime stack. The only algorithmic control-flow branch in this kernel is loop termination. Machine-code branch behavior and performance still require inspection and RDTSCP measurement.

For compact programs, reserve a reference tag bit for terminals and use local node/outcome indices in the remaining bits. Programs exceeding the compact index range use a wider serialized format selected outside the traversal loop; never truncate indices. Likewise, general filtered or large-context programs require a probe plan or wider backend, not signed-16-bit offset assumptions. The compiler’s semantic IR retains full-width positions and lookup filtering.

Exact alphabet compression, not approximate matching

Two glyph IDs may share a matching symbol only if they have identical membership in every relevant predicate. Keep the original glyph ID for actions and output. In the inspected JetBrains calt feature, the 12,138 glyph IDs collapse into exactly 32 such profiles, including the all-false profile. Thus every predicate is a 32-bit mask. All 388,416 glyph/predicate membership checks agreed with the original sets.

A full 32-symbol successor row costs 64 bytes per node before metadata, so use such rows only where their speed/space tradeoff is demonstrated.

3. Construction: ordered graph, then flat arrays

  1. Normalize the font language

    Resolve extension wrappers and binary offsets. Preserve lookup/stage order, rule/subtable priority, glyph predicates, input boundaries, filters, ordered actions, feature guards, and resume behavior. Represent positions at full width in the compiler.

  2. Build exact matching symbols

    Intern predicate sets. Partition glyphs by complete predicate-membership signatures. Build paged classification tables and predicate masks. Glyphs equivalent for matching are not necessarily interchangeable in action payloads.

  3. Construct explicit priority continuations

    Work backward from the lowest-priority rule. Its failures go to no-match. For each earlier rule, all failed tests go to the already-built next-rule entry, and its final successful test goes to its own terminal. A blocker is an accepting terminal, never a failure edge.

    fallback = NO_MATCH
for rule in reverse(priority_order):
    hit = terminal(rule)
    for test in reverse(rule.tests):
        hit = node(test.probe, test.predicate,
                   miss=fallback, hit=hit)
    fallback = hit
root = fallback

  4. Share only behaviorally identical nodes

    Node identity includes its probe, predicate, both continuations, and applicable execution environment. Different miss continuations require distinct nodes even when a textual prefix is identical. This naturally implements priority-preserving branch duplication. Common-test hoisting must preserve complete-rule order.

  5. Fuse proven local rewrite chains

    Symbolically compose bounded transitions such as the guarded <=> chain into one compound result. Preserve feature masks, blockers, complete reads/writes, source mapping, and resume position. Do not fuse across unproven dependencies or re-run completed lookups to a fixed point. Retain ordered execution where fusion is not established.

  6. Flatten and pack

    Assign local integer IDs, choose the narrowest safe backend, order likely success paths nearby, emit nodes/masks/roots/hot outcomes, and serialize payloads separately. Relocate all references and discard temporary construction objects. Report actual bytes by section, path lengths, duplicated nodes, and fusion results.

  7. Verify semantics, then measure

    Compare compiled and original execution for priority shadows, blockers, overlapping contexts, feature ranges, boundaries, filtering, ordered mutations, expansion, and reverse processing. Exercise current equivalence workloads and real fonts. Inspect assembly and compare direct RDTSCP timings against an uninstrumented control. No shaping implementation or performance result is claimed by this proposal.

4. Scheduling and storage boundaries

Payload latency

Once a terminal is known, its payload address can be prefetched and an indexed action queued. Overlap that fetch with independent work. A dependent next match must wait until preceding effects are visible.

The A → B → C node chain itself contains dependent loads. Uniform instructions do not make those loads parallel. Interleaving independent traversals is a separate optimization with dependency requirements.

Dead slots and safe probes

Use an explicit dead-slot representation; never use SPC or glyph zero. A tombstone is absent from the logical sequence, not a nonmatching visible glyph. Filtering/dead-slot handling belongs to the live-sequence accessor before or around this compact kernel.

Bounds-safe padding or checked probe resolution must make boundary probes valid. Arbitrary insertion needs storage beyond tombstones. Final compaction must preserve advances, attachment metadata, and source mapping.

5. Risks and decision

Sharing a prefix with the wrong priority continuationHIGHInclude both outgoing continuations in node identity; duplicate when necessary.

Branch-free code performs more dependent workMEDIUMMeasure actual traversal and memory costs. Do not pad all failures to worst-case path length by default.

Proposed baseline

Choose compact predicate nodes with two explicit destinations, separate action payloads, and priority-safe duplication. Build the ordered graph directly; an ordinary trie is optional construction scaffolding, not the semantic model. Select dense transition rows only when measured benefits justify their footprint.
